Ideal Git Branching Strategy for 2 Environments

Dev Branch
All new features, bug fixes, and infrastructure changes are first merged into the develop branch. Deployments from this branch target the dev environment for testing and validation.

Main Branch
Once changes are tested and stable in develop, they are merged into the main branch. Deployments from main target the production environment.

Pull Requests
All changes should be submitted as pull requests against develop. After review and successful CI validation, they are merged.
When ready for production, create a pull request from develop to main.

So,
develop → Dev environment

main → Production environment

Only tested and reviewed code reaches production.
